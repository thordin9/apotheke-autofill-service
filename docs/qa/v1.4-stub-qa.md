**M3. The secret-redaction filter does nothing for the service's own log records.** `install_redaction` adds `_Redact` to the **root logger**. Python runs a logger's filters only for records created on that logger, not for records propagated from `app.*`, `uvicorn.*` or `httpx`. No current code path logs the token or account id (S8 is clean), so this is a broken safety net, not a leak. But the docs and code comments present it as a guarantee. Repro: `test_redaction_filter_covers_module_loggers` (a warning on `app.backends.cloudflare` containing the token reaches the root handler unscrubbed). Fix: attach the filter to handlers (diff), or more robustly use a `logging.setLogRecordFactory` wrapper that scrubs `msg`/`args` when the record is created, and test it through a real handler.

**M4. `/healthz` `serving: "fallback"` and `/v1/info` fallback `state: ready, can_serve: true` are static config flags.** They stay true after a 5035, a 401 or (on the final head) a used-up Neuron budget, so an operator or a future Apotheke reading `serving` is misled. Repro: `test_healthz_serving_fallback_even_when_cf_cannot_serve`. Fix: derive `can_serve` from the CF backend's last outcome (paid-plan or auth rejection, budget remaining > 0, recent rate-limit) and report `state` as `ready|rejected|budget_exhausted|rate_limited`; emit `serving` only when `can_serve`.

### B.3 Findings at bb3c87e

#### High

**H2. With Ollama cold, the CF slice uses up the time Ollama needs, so a CF hang can never fall back.**
- The slice is `min(CF_TIMEOUT_S, deadline − reserve)`, which is 45 − 35 = 10 s when Ollama is cold. The check in `_run_ollama` is `remaining < needed`.
- After the 10 s `wait_for` timeout plus a few ms of overhead, `remaining` is 34.99 s, below the 35 s reserve. The client always gets 503 `not enough time left to fall back to the local model`.
- The same happens with any settings where the reserve, not `CF_TIMEOUT_S`, limits the slice.
- It fails safe (503 + Retry-After after about 10 s, under the 50 s client timeout), but the documented "cold, then Ollama answers" path never runs. Warm at the shipped defaults isn't affected: `CF_TIMEOUT_S` caps the slice at 20 s, leaving 25 s.

Repro: `probes::test_deadline_shipped_defaults_cf_hang_falls_back` (503 after 10.03 s) and `test_deadline_cf_hang_with_warm_ollama` (small-scale settings where the reserve limits the slice).

Fix: take a margin off the slice, for example `min(CF_TIMEOUT_S, deadline − reserve − 1.0)`, and check it at startup. Or compare `remaining` against `reserve − margin`. Add a test that hangs CF at the shipped defaults with Ollama cold.

#### Medium

**M5. A clock that goes backwards resets the budget.** The state file stores the UTC day, and any day other than today starts a new day at 0. That includes an earlier day, which is what a stale clock produces. A box that boots with a stale RTC before NTP syncs (or after a manual clock fix) gets a fresh 6000.

Repro: `test_budget_clock_rollback_does_not_reset`.

Fix: roll over only when today is after the stored day. When today is before it, keep the stored counter (or treat the budget as exhausted) and log once.

**M6. A v1.3 env with `BACKEND=ollama` and no `FALLBACK_BACKEND` no longer starts.** The new default `FALLBACK_BACKEND=ollama` together with `BACKEND=ollama` fails `validate_runtime`. `deploy/jetson/run-service.sh` works around this, but `docker run` or `docker compose` with an existing v1.3 env file crashes at startup (the image default changed too).

Repro: `test_old_ollama_only_env_still_starts`.

Fix: when `BACKEND=ollama` and `FALLBACK_BACKEND` is unset, default the fallback to `none`. Refuse only an explicit `FALLBACK_BACKEND=ollama` with `BACKEND=ollama`. Note it under "Upgrading" in the CHANGELOG.

**M9. The gitleaks allowlist can hide a real token that shares a match with a placeholder.** The allowlist uses `regexTarget = "match"` with `^generate-a-random-token>` (anchored at the start only) and `Bearer ci-token'$`. The `curl-auth-header` rule reports one match per curl command, ending at the first `Authorization` header.
