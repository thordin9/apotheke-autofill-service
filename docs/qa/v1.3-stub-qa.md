## Findings
- **H1 (high, blocking): client categories dropped.** The prompt and `format` enum are the fixed bench list, not `context.categories` (main's behaviour). Custom categories are never suggested. Pre-2.3 Apotheke databases lose Clothing/Shoes/Books/Lighting answers completely, because a strict snap drops them. Fix: use the client's categories and fall back to the v3_lean list when there are none. With no categories, or the bench list in bench order, the prompt and schema are still byte-identical to the winning files (suggested diff, tests updated). Correct the "unchanged" wording in the CHANGELOG and `docs/api-v1.md`.
- **M1 (medium): a lone surrogate in an identity value → 500.** Drop `Cs` code points in `clean_identity`.
- **M2 (medium): F6 Retry-After ignores the existing rules.** It uses the load estimate without the max(2 s, 30 %) margin and has no cap at BACKEND_TIMEOUT_S+5. It reached 63 at T=45, which Apotheke won't retry. Fix: `_load_budget_s` + the same cap.
- **M3 (medium): `state` stays `loading` on an idle, fully loaded model** after warm-up or a restart. The docs tell clients to use `state`, so a client would show "loading" until someone sends a photo. Suggest marking `warm` after a successful background `/api/generate` load. If it stays as is, document it, and Apotheke v2.5 must not gate on `warm`.
- **L1 (low): log redaction gaps** for truncated list/object values, spaced keys and `value` siblings, at WARNING even with `OLLAMA_LOG_RAW=0`. The suggested diff closes these. Prose and escaped HTTP-error bodies can't be redacted reliably, so add a docs note.
- **L2 (low):** control and bidi-override characters pass through, and the 128 cut can split a combining or ZWJ sequence. The suggested diff drops Cc/Cs and U+202A–202E/U+2066–2069 (keeping RLM/LRM/ZWJ) and cuts on a cluster-safe boundary.
- **L3 (low):** there's no 1.3.0 version bump. Add a `## 1.3.0` CHANGELOG heading (and pyproject if it's meant to track releases).
- **L4 (low):** unauthenticated `/healthz` now lists model ids, state, VRAM and latency. Consider keeping `/healthz` to `status`.
- **L5 (low, docs):** `docs/deploy-jetson.md`: the new `/healthz` sentence was inserted between "…can't stretch the wait." and "It must be a positive whole number…", so "It" no longer refers to `WAIT_S`. The CHANGELOG entry from #18 (on main) still says "InternVL3/SmolVLM2 are CPU-only (~80–110 s/photo)" four lines before saying they aren't, and has a double blank line. That one is for ITAdvisor; #20 doesn't add it.
- **I1:** `/healthz` stays degraded on a stale snapshot while `/api/ps` errors. **I2:** partial offload isn't flagged (only 0). **I3:** an unload plus an external reload between two `/api/ps` reads keeps a stale `warm`. **I4:** the "would time out" RA doesn't include unfinished load. **I5:** F6 doesn't count a queued switch ahead when the refused request is for the in-flight model.

### Findings (round 2)
- H1, M1, M2, M3, L1, L2, L3, L4 and L5 from round 1: **fixed** (evidence above).
- **I1 (low, docs):** `docs/api-v1.md` says an `/api/ps` failure "leaves the probe at `ok`". That holds only when the last successful read wasn't degraded. After a degraded read, `/api/ps` 404 or a timeout keeps **503** on the cached snapshot. This is fine for the detector (it stays red until Ollama answers again), but the sentence should say "keeps the last result".
- **Known item for Apotheke v2.5 (not a blocker, PM decision to keep the 503):** v2.4.1's Test connection reports a degraded service as "HTTP 503 – is this the autofill service (API v1)?". v2.5 should read `status: "degraded"` from the `/healthz` body and say the service is running on CPU. Suggestions still work while degraded.
- **Rollback note:** if a deploy meets a CPU-only Ollama, the new container's `/healthz` is 503, so `run-service.sh` times out and rolls back. The old container (before v1.3) then answers 200 even on CPU, so after a rollback the board looks healthy. Check `ollama ps` / `size_vram` by hand after any rollback.
- **I6:** the load counts as successful on HTTP < 400 without checking `done: true` in the body.
- **I7 (already on main):** a category name containing a newline breaks the prompt's category line (`"a\nb"`). Main put client categories into the prompt the same way. Consider dropping control characters in `_context_list`.
- **I8 (wording):** "accuracy matches the Feature 9 sweep" was measured with the bench list only; client lists are untested on hardware.
- Round-1 I2–I5 unchanged (partial offload not flagged, stale `warm` after an external unload + reload between reads, "would time out" RA without the owed load, F6 with a queued switch ahead).
- Cosmetic: `## [1.3.0]` has no date or link reference; #21's entry on main still says "+0.8 s" next to the +0.7 s retime.
